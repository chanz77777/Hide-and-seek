# Vercel デプロイ手順

お絵描きかくれんぼを Vercel に載せて、インターネット越しに複数人で遊べるようにするための手順です。
コードは作成済みで、ローカルでは 3 人での 1 ラウンドを通しで確認しています。デプロイとクラウド側の設定は、この手順に沿って人の手で行ってください。

## 1. 全体の構成

```
ブラウザ（各プレイヤー）
  │  静的ファイル: public/（HTML・JS・Three.js）
  │  約 1 秒ごとに部屋の状態を取りに行く（ポーリング）
  ▼
Vercel Functions（api/*.js, Node.js）
  ├─ 部屋の状態 ……… Upstash Redis（Vercel Marketplace から追加）
  └─ 画像の保存 ……… Vercel Blob（床の絵・体の塗り）
```

- Vercel の関数は WebSocket を張り続けられないため、リアルタイム通信の代わりに 1 秒ごとのポーリングにしています。かくれんぼは操作の頻度が低いので、これで十分に遊べます。
- 時間切れなどの切り替えはタイマーを使わず、状態を読むたびにサーバーが判定します。そのため Cron は不要です。
- 通信の取り決めは `docs/online-protocol.md` にあります。

| 場所 | 中身 |
|---|---|
| `public/` | ゲーム本体（`index.html`、`js/`、`vendor/three.min.js`） |
| `api/` | `create` `join` `state` `action` `upload` `cursor` の 6 つの関数 |
| `lib/` | ゲームのルール（`game.js`）、Redis（`store.js`）、Blob（`blob.js`） |
| `dev/` | ローカル開発サーバーと API の自動テスト |
| `vercel.json` | 静的ファイルの場所（`public`）の指定 |

## 2. 事前に用意するもの

- Vercel のアカウント。個人の検証なら Hobby プラン（無料）で足ります。業務や商用で使う場合は Pro プランが必要です。使うアカウントやチームは事前に決めてください。
- GitHub などの Git リポジトリ（Git 連携でデプロイする場合）。今の作業フォルダはまだ Git 管理されていません。
- ローカル確認用の Node.js 18 以上（このマシンは 18.19.1）。

## 3. デプロイ前のローカル確認

```bash
cd game
npm install
npm test          # API の自動テスト（77 項目）
npm run dev       # http://localhost:3000 で起動
```

- ブラウザを 2 つ（片方はシークレットウィンドウ）開き、片方で「部屋を作る」、もう片方で部屋コードを入れて「参加する」と、ローカルで対戦できます。
- 環境変数がないときは、部屋の状態をメモリに、画像を `dev/.data/uploads/` に保存します。

## 4. デプロイ手順（Git 連携、推奨）

1. **リポジトリに上げる**
   - `game/` フォルダをリポジトリに push します。`.gitignore` 済みなので `node_modules` や `dev/.data` は上がりません。
   - `game/` がリポジトリのルートでない場合は、手順 2 で Root Directory を指定します。
2. **Vercel でプロジェクトを作る**
   - Vercel のダッシュボードで「Add New → Project」を選び、リポジトリを Import します。
   - Root Directory はリポジトリ内の `game/` の場所にします（ルートなら空欄）。
   - Framework Preset は「Other」にします。
   - Build Command と Install Command は既定のままで構いません。
   - Output Directory は `vercel.json` の `public` が使われます。
   - この時点で一度デプロイされます。ただし Redis と Blob がまだないので、オンライン対戦は動きません。
3. **Node.js のバージョン**
   - Project Settings → General → Node.js Version で 20.x 以上を選びます。
4. **関数のリージョン（推奨）**
   - Project Settings → Functions → Function Region で東京（`hnd1`）を選びます。
   - 既定は米国東部です。日本から遊ぶなら、東京にしたほうが 1 秒ごとの通信が軽くなります。
5. **Redis（Upstash）をつなぐ**
   - プロジェクトの Storage タブ →「Create Database」→ Marketplace の「Upstash（Redis）」を選びます。
   - リージョンは関数と近い場所（東京など）にします。
   - 作成後、このプロジェクトに Connect します。
   - 環境変数 `KV_REST_API_URL` と `KV_REST_API_TOKEN`（または `UPSTASH_REDIS_REST_URL` と `UPSTASH_REDIS_REST_TOKEN`）が自動で入ります。コードはどちらの名前でも動きます。
6. **Blob をつなぐ**
   - Storage タブ →「Create Database」→「Blob」で作成し、このプロジェクトに Connect します。
   - 環境変数 `BLOB_READ_WRITE_TOKEN` が自動で入ります。
7. **再デプロイする**
   - 環境変数は、追加したあとのデプロイから有効になります。
   - Deployments タブで最新のデプロイを「Redeploy」してください。Git に push しても再デプロイされます。

### CLI でデプロイする場合

```bash
npm i -g vercel
cd game
vercel login
vercel link        # プロジェクトとひもづけ
vercel             # プレビュー環境へ
vercel --prod      # 本番へ
```

Redis と Blob の接続は、ダッシュボードで手順 5 と 6 を行ってください。
`vercel env pull` を使うと、接続情報がローカルの `.env` ファイルに書き出されます。このファイルは Git に上げないでください。`.gitignore` には含めてあります。

## 5. デプロイ後の確認

1. 発行された URL を開き、タイトル画面に「オンラインで遊ぶ」の欄が出ることを確認します。`file://` で開いた場合は出ません。
2. 名前を入れて「部屋を作る」を押し、4 文字の部屋コードが出ることを確認します。
3. 別の端末やシークレットウィンドウで「招待リンクをコピー」の URL を開き、参加します。
4. ホストが「自動生成」か「画像を選ぶ…」で床を決め、見つける人を選んで「はじめる」を押します。
5. 隠れる人が「準備完了」を押すと、見つける人の画面が捜索に切り替わります。爆撃の結果が全員に届けば完了です。

### うまく動かないとき

| 症状 | 確認すること |
|---|---|
| 「部屋を作る」でエラー | Storage に Redis が Connect されているか。接続後に再デプロイしたか |
| 床の絵を送れない | Blob が Connect されているか（`BLOB_READ_WRITE_TOKEN`） |
| 床が表示されない・スポイトが効かない | Blob の画像の読み込みがブラウザの開発者ツールでブロックされていないか（CORS） |
| API が 404 | Root Directory が `game/` を指しているか。`api/` フォルダがデプロイに含まれているか |
| API が 500 | Vercel の Logs タブで関数のエラーを確認する |

## 6. 費用と使用量の目安

各サービスの無料枠や料金は変わることがあります。数値は必ず各社の料金ページで確認してください。

- **Vercel 関数**: 1 人が 1 秒に 1 回、状態を取りに行きます。捜索中だけは照準を見せるため 0.4 秒に 1 回になり、見つける人は照準を 0.25 秒に 1 回送ります。5 人・準備 90 秒・捜索 60 秒のラウンドなら、1 ラウンドで約 1,500〜1,700 回の呼び出しになります。
- **Upstash Redis**: 状態の取得 1 回で、Redis の命令を 2〜3 回使います。上の例なら 1 ラウンドで数千命令です。
- **Vercel Blob**: 1 ラウンドごとに、床の画像（約 0.5〜1.5 MB）と隠れる人 1 人につき体の画像（数百 KB）が保存されます。今は古い画像を消す処理がないため、遊ぶほど保存容量が増えます（今後の課題に記載）。

## 7. セキュリティと注意点

- アカウント登録はありません。参加者は部屋コードと、ブラウザに保存されるランダムな合言葉（トークン）だけで識別します。部屋コードを知っていれば誰でも参加できます。
- 部屋は最後の更新から 3 時間で自動的に消えます。1 部屋の上限は 10 人です。
- Blob の画像は公開 URL です。URL は推測しにくいランダムな名前ですが、知っていれば誰でも見られます。個人情報や社外秘の画像を床に使わないでください。
- アップロードは 1 枚 4 MB まで、形式は WebP・JPEG・PNG のみです。ファイルの中身が宣言した形式と一致するかも確認しています。
- `@vercel/blob` 1.1.1 には `npm audit` で 3 件の指摘があります（依存する `undici` などの、マルチパート解析に関するもの）。ローカルの Node が 18 なので 1.x にしています。Vercel 側は Node 20 以上なので、ローカルも Node 20 にそろえたら 2.x に上げてください。

## 8. 今の制限と今後の課題

- 状態の反映に最大 1 秒ほどの遅れがあります。
- ロビーの「接続なし」の表示は、部屋に何か変化があったときにしか更新されません。
- Blob の古い画像を消す処理がありません。部屋の終了時に消すか、Cron で定期的に消す必要があります。
- 見つける人は 1 ラウンドに 1 人です。ラウンドごとの役割交代は、ホストがロビーで「見つける人にする」を押して行います。
- 同じ PC の別タブ対戦と 1 台での交代は、オンラインとは別にそのまま使えます。`public/index.html` を直接開いた場合はこちらだけになります。
